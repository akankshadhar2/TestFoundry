# Presenter script (~10 minutes)

**Story:** *AI makes test doubles fast and cheap. Integration against the real resource keeps them honest.*

Use a large terminal font, a dark theme, and a window at least 120 columns wide. Keep an editor
open next to the terminal for the "Open …" moments.

---

## Day before: rehearsal (with real keys)

1. `python preflight.py` should print READY with no warnings.
2. Run the full flow, steps 0–6 below, exactly as on stage. Step 4 creates
   `recordings/stripe/real_run.json`, which is your offline safety net (`--backend=replay`).
3. If everything went well, run `python save_backup.py`. It freezes the real recordings, Claude's
   fixtures and Claude's fake as the backup. It refuses if the planted flaw is still in place or
   the fake fails.
4. `python reset.py`
5. Note how long steps 1, 2 and 5 took. Claude's timing varies, and `CLAUDE_EFFORT=low` in `.env`
   speeds it up.

## Demo day: 10 minutes before

1. `python preflight.py`
2. Network good: `python reset.py`. Network bad: `python reset.py --from-backup`, then start at step 3.
3. Clear the terminal and set the font size.

---

## Script

### Step 0 · Record real Stripe (≈ 45 s)
```bash
python record.py
```
- **Point at:** the field counts ("39 top-level fields, … levels deep") and the state machine.
  Then open `recordings/stripe/record/successful_charge.json` and scroll it.
- **Say:** "This is one real payment from Stripe's test mode. Look at the size of it. A PaymentIntent
  is a state machine with charges and refunds hanging off it. Writing a faithful fake by hand
  takes days. We only recorded three calls."

### Step 1 · Claude generates fixtures (≈ 1 min)
```bash
python generate_fixtures.py
```
- **Point at:** files appearing one by one in parallel, each with a one-line outcome, and the
  final "N generated by Claude" line.
- **Say:** "We recorded three scenarios. Claude has to *extrapolate* the other six: refunds of
  declined payments, double refunds, amounts below the minimum. That's where AI guesses go wrong,
  so keep an eye on them."

### Step 2 · Claude writes the fake (≈ 1–2 min)
```bash
python generate_fake.py
```
- **Point at:** the code streaming in, then the self-check ("structure OK", "fake passes every
  fixture"). If you see "AI self-check found N problems, fixing…", point at it, because it's a
  good moment. Then open `generated/stripe/fake_stripe.py`.
- **Say:** "Claude writes the fake from the fixtures. Then we check it for real: it must import,
  match our interface exactly, use no network, and pass every fixture. If not, it fixes itself."

### (Optional) Plant a flaw (≈ 15 s)
```bash
python inject_flaw.py
```
Use this if you want a guaranteed red in step 4. It's recommended unless rehearsal showed natural
divergences.
- **Say:** "To make sure we see it, I've planted a realistic mistake: the fake now believes a
  declined payment can be refunded."

### Step 3 · Tests against the fake (≈ 15 s)
```bash
python -m pytest --backend=fake
```
- **Point at:** all green, and the "⚡ 15 tests in 0.0x s, no network" line.
- **Say:** "Fifteen tests in a few hundredths of a second, with no network or API keys. This is
  what you'd run on every save and in CI."

### Step 4 · The same tests against real Stripe (≈ 30 s)
```bash
python -m pytest --backend=real
```
- **Point at:** the red test(s) and the diff: "AI fixture expected … / real Stripe did …".
- **Say:** "Same tests, real Stripe. Here's where the AI was confidently wrong. The fake passed
  because it was built from those wrong expectations. Only the real service can catch this."

### Step 5 · Repair from reality (≈ 1–2 min)
```bash
python repair_fake.py
```
- **Point at:** the mismatch list, "fixture X corrected from real Stripe", the streamed patch, and
  the green self-check.
- **Say:** "Now real Stripe is the source of truth. The wrong fixtures are replaced with real
  responses mechanically, with no AI involved. Then Claude patches the fake to match, and it
  removes my planted flaw too."

### Step 6 · Both green (≈ 30 s)
```bash
python -m pytest --backend=fake
python -m pytest --backend=real
```
- **Say:** "Fast and honest. The fake is cheap to make and cheap to run, and integration against
  the real thing keeps it truthful. Swapping Stripe for another service means writing one provider
  module."

## Recovery table

| Problem on stage | Do this |
|---|---|
| Claude API down or slow | Scripts fall back to the backup automatically. Say "here's the version it generated in rehearsal" |
| Wi-Fi dies before step 4 | `python -m pytest --backend=replay` (real responses from rehearsal) |
| Step 4 shows no failures | Run `python inject_flaw.py`, then rerun steps 3–4 |
| Fake fails in step 3 | `python repair_fake.py` or `python reset.py --from-backup` |
| Repair can't produce a passing fake | `python generate_fake.py` (rebuilds from the corrected fixtures) or `python reset.py --from-backup` |
| Anything weird | `python reset.py --from-backup`, then continue from step 3 |

Every script prints exactly what it did, including when it used a backup. If you're asked, be
upfront: "that one came from the rehearsal run."
